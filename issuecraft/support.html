What to include

These four things let most problems be diagnosed from the first message:

  • Your Jira site URL (for example yourcompany.atlassian.net)
  • The project key you were creating in, the template you picked, and the issue key that was created (it appears on the confirmation, and it is also in the app's log line)
  • Whether your Jira interface is in a language other than English
  • What you expected to see and what you saw instead — a screenshot helps a lot

Common questions

A template is missing from the list.
Templates are matched to the issue types the selected project can actually create. If a project has no Bug issue type, the Bug template is hidden — and the app tells you how many templates were hidden and why, rather than showing a template that would fail when you pressed the button. If you think a template should be there, check the project's issue types first.

I changed the issue type and the description no longer fits.
That is allowed on purpose, and the app warns you when the issue type differs from the one the template was written for. The description is created exactly as written — the app does not silently rewrite it for the new type.

My priority was not set.
Priorities are per-site and often localised, so the app only offers the ones your project actually has. If the template's default priority does not exist in your project, the app leaves the priority at the project default and tells you — it never guesses a substitute.

My label came out with dashes in it.
Jira labels cannot contain spaces, so needs triage is created as needs-triage. The app says so on the confirmation rather than changing it quietly. Duplicate labels are dropped, also with a note.

A component I typed was not applied.
Only components that exist in the selected project can be set. Anything else is dropped and listed on the confirmation. This is deliberate: inventing a component would either fail the creation or attach your issue to the wrong thing.

My summary was shortened.
Jira caps a summary at 255 characters. The app cuts it to fit and tells you it did. It also puts the summary on one line, because Jira does not accept line breaks there.

Nothing happened when I pressed create.
Nothing is created until the request succeeds, so a failure leaves nothing behind — there is no half-made issue to clean up. The page shows the reason Jira gave. The most common causes are not having permission to create in that project, or the project no longer accepting that issue type.

Two people pressed create at the same time.
The app does not de-duplicate. If you need one issue per report, that is still a human decision — the app creates exactly what you confirm, once per press. There is no automatic retry and no background job, so a double press creates two issues.

Who can install this?
A Jira administrator installs it for the site. Because the app acts as the person using it, it cannot do anything an individual user could not do themselves — installing it does not grant anyone new access to any project.

Privacy and security

What the app reads, what it creates, and the fact that it stores nothing are documented in the privacy policy; how it is built and which scopes it asks for are on the security page. In short: it reads the projects you can file work in, it creates the one issue you confirm, it keeps no app storage, and it sends nothing to any external service.
