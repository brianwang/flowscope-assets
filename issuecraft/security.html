Security Policy

Issue Templates for Jira

Last updated: 5 October 2026

This app is published on the Atlassian Marketplace by the partner andy20261001. This page states how the app is built and what it can and cannot reach. It is written to match the app's source code and its Forge manifest, not to describe a general policy.

1. Where the code runs

ComponentWhere it executes
Backend (resolver) Atlassian Forge, on Atlassian's infrastructure (nodejs22.x runtime). No partner-operated server is involved.
Frontend (the app's page) The end user's browser, inside the Jira page. The template list and the form are drawn there; no remote asset is loaded.

There is no infrastructure operated by the publisher. The app has no server, no database and no hosting of its own, and it keeps no app storage.

2. Permissions and identity

The app requests exactly two OAuth scopes:

  • read:jira-work — to read the projects you can file work in, and their issue types, components and priorities.
  • write:jira-work — to create the one issue you confirm. This app writes; a read-only scope would make it do nothing.

Every Jira request is made as the user who is using the app, using Forge's built-in OAuth. The app never uses an administrative identity, and it cannot create an issue that you could not have created yourself by hand. If you lack permission to create issues in a project, the app does not offer it — that list comes from Jira, not from us.

The app does not claim the "Runs on Atlassian" badge. That badge is for apps that run entirely on Atlassian's platform without egress and without extended data access. This app does declare no egress, but it requests a write scope — it creates issues — so it is outside what the badge covers, and it makes no claim to it. Where the app relies on Atlassian's own controls (infrastructure, OAuth, logging), those are described in Atlassian's documentation, not here.

3. Network access

The app makes no outbound request to any host other than Jira's own REST API. There is no analytics, no telemetry, no crash reporting, no advertising SDK and no third-party service of any kind. Its Forge manifest declares no external egress domains, so it is structurally incapable of sending your data anywhere but Atlassian.

4. Secrets and credentials

The app never asks for an Atlassian API token, a password, or any other credential. That includes your credentials and any third-party service's. Authorization is handled entirely by Atlassian's OAuth flow; the app stores no token and no secret, and there is nothing for a user or an administrator to generate, copy or paste.

The app does not connect to any external system, so it does not collect credentials for one either.

5. What is read and written

What the app reads from Jira, exactly what it creates, what it stores (nothing) and what it logs are described in full in the Privacy Policy. In summary: it reads the projects you can file work in and their issue types, components and priorities; it creates one issue when you press the button; it keeps no app storage; it writes one log line containing the created issue key, project key, the creator's account ID and the template used.

6. Input handling

  • The project key is validated before it is ever placed in a URL, against a strict pattern, and every request path is required to begin with the Jira REST prefix. A project key that does not match is refused rather than encoded and sent.
  • Everything else travels in the request body, never in a URL.
  • The server re-reads the project's schema before every creation and recomputes the issue from it. A modified page cannot make the app send a field or a value the project does not accept.
  • No user input is rendered as HTML. The app's interface has no innerHTML and no HTML injection path; what you type is text.

7. Data residency

The app processes data exclusively within Atlassian apps and services. It defines no data egress, so there is no external location for data to reside in.

8. Reporting a vulnerability

Please email wangxydlut@gmail.com with a description of the issue and, where possible, the steps to reproduce it. Please do not open a public issue for a security report.

This is a small app maintained by one person. Reports are handled on a best-effort basis and there is no guaranteed response time and no bug bounty programme.

9. What this page does not claim

The app holds no security certification, no independent audit and no compliance attestation (for example SOC 2, ISO 27001 or a completed CAIQ). Nothing on this page should be read as claiming otherwise.
