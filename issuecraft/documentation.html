Issue Templates for Jira

Last updated: 5 October 2026

This page covers everything the app does. It is written to match the app's behaviour, including the parts that are unflattering — where the app changes something you typed, this page says so, and the app says so on screen too.

1. What the app does

It is a Jira app that turns filing work into picking a template. You choose a project, pick a template, adjust what you need, and create the issue. The issue type, summary, description, labels and components come from the template, so everyone on the team files work the same way.

The app opens as a full page under Apps in Jira. It creates one issue per press of the button: nothing is created until you press it, and there is no bulk mode and no scheduled action.

2. Requirements

  • Jira Cloud.
  • Permission to create issues in the project you want to file against — the app only lists the projects where you have it.
  • Nothing else. There is nothing to configure, no field mapping to set up and no administrator step beyond installing the app.

3. Using it

  1. Open Apps → Issue Templates.
  2. Pick a project. The app reads that project's issue types, components and priorities.
  3. Pick a template from the list on the left. Templates that this project cannot create are hidden, with a count and the reason — see section 5.
  4. Adjust the issue type, summary, description, labels, priority and components if you need to.
  5. Press Create issue. The confirmation shows the issue key and a link to it.

The issue type column lists preferences in order: the app uses the first one the selected project actually has. A template with no available issue type in that project is hidden rather than shown and then failed.

The templates are fixed text stored in the app. They are not generated, and nothing you type is sent anywhere to produce them.

5. Which templates you see

Issue types are matched on their internal (untranslated) name first, and only then on the name your site displays. That is deliberate: on a site running in Chinese, the Bug issue type is displayed as 缺陷, and a template matched by the displayed name alone would find nothing. Matching on the internal name first means the same template set works on every localisation; the displayed name is kept as a fallback for sites that rename their types.

Two consequences worth knowing:

  • Sub-task types are never used. A sub-task needs a parent, and choosing a parent is a decision outside this app. A project that only has sub-tasks available will show no templates, and will say so.
  • Renamed issue types may not match. If your site has renamed its issue types (for example Bug → Defect), the internal name is usually unchanged and matching still works. If it does not match, the template is hidden — and you can still pick a different template and set the issue type by hand.

6. Writing the description

The description box is plain text with a small amount of markup. It is converted to Jira's document format when it is sent, so the result is a real formatted description, not a wall of plain text.

## A heading
### A smaller heading

A paragraph. **bold**, *italic* and `monospace`.

- a bullet
- [ ] a checkbox that is not done
- [x] a checkbox that is done

1. a numbered item
2. another

---            (a horizontal rule)

```js
a fenced code block
```
Checkboxes are characters, not Jira task items. Jira's issue description format has no checkbox element, so - [ ] becomes a bullet beginning with ☐ and - [x] becomes one beginning with ☑. They read the same and are checked by hand — they are not clickable, and they do not appear in a to-do list. The app does this rather than emitting a task item that Jira would reject and fail the whole creation.

Two placeholders are filled in for you at the moment you press create:

PlaceholderBecomes
{{date}}Today's date, as 2026-10-05
{{project}}The project key you selected, as PLAT

A placeholder the app does not recognise is left exactly as typed. If you mistype {{dat}}, it stays in the issue text and you can see it. It is not replaced with an empty string.

7. What the app adjusts, and what it refuses

Where the app has to change or drop something you typed, it says so on the confirmation — it never adjusts silently. This table is the complete list.

SituationWhat happens
Summary contains a line break or a tabIt is put on one line, and reported
Summary is longer than 255 charactersIt is cut to 255, and reported
A label contains a spaceSpaces become dashes (needs triage → needs-triage), and reported
Two labels differ only in caseThe duplicate is dropped, and reported
A component is not in the projectIt is dropped, and reported
The priority does not exist in the projectPriority is left at the project default, and reported

And what the app refuses — these stop the creation instead of guessing:

  • An empty summary. Nothing is created.
  • No issue type. Nothing is created.
  • A project or issue type you cannot create in. The app re-checks this server-side against Jira itself before creating anything.
An empty description is not sent at all. If you clear the description box, the app omits the field rather than sending an empty document — so a project's own default description (if your Jira has one configured for that issue type) is not overwritten with nothing. An empty box means "say nothing", not "erase what Jira would have put there".

8. Priorities and localisation

Priorities are per-site and may be localised. On a site with a partially translated priority scheme, the list can legitimately contain both a localised name and an English one — for example 严重 alongside Highest. The app offers exactly the priorities your project reports and matches on the name it is given. It never maps "Critical" onto some other priority because the name looks similar.

9. Languages

The app interface is available in English and Chinese (Simplified). Issue type, component and priority names are shown as your Jira displays them, because they are your Jira's values, not the app's text.

10. Data and privacy

The app reads the projects you can file work in and their issue types, components and priorities, using a read scope; it creates the one issue you confirm, using a write scope; it keeps no app storage of its own; and it sends nothing to any external service. The full description of what is read, created, stored and logged is in the privacy policy, and the scopes and security posture are on the security page.
