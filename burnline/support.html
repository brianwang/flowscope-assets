What to include

These four things make the difference between a guess and a diagnosis:

  • your Jira site URL, and the JQL filter configured on the gadget
  • the Done status you selected (its name, and its numeric ID if you know it)
  • what you expected the chart to show, and what it showed instead
  • a screenshot of the gadget, including the summary line underneath the chart

The summary line under the chart carries the numbers we would otherwise have to ask you for: scope, delivered, remaining, the throughput figure with its sample size, and any items that were excluded. Please do not remove it from the screenshot.

Common questions

The chart is empty

The filter probably matches nothing, or matches only items that were already done before the history window began. Use the Preview button in the gadget's settings — it returns a count without drawing anything, so you can tell whether the filter itself is wrong.

Nothing is counted as delivered

Check the Done status setting. The chart counts an item as delivered only when it entered that exact status. If your workflow finishes work in a status other than the one selected, everything will look unfinished. The chart reports items that are in a done-category status but never passed through your chosen status, so a number under that note is the signal that this setting is wrong.

There is no forecast line

That is deliberate. A percentile line is only drawn when the history window contains enough whole weeks to support it: 5 weeks for the 50th percentile, 10 for the 70th, 20 for the 85th, 40 for the 95th. With the default 12-week window you will normally see the 50th and 70th. See documentation for why.

The forecast date looks too optimistic or too pessimistic

It is a projection from your own recent throughput, nothing more. If the last few weeks were unusual, the forecast will be too. Widening the history window makes it steadier; narrowing it makes it more responsive.
