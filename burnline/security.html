Security

Burnline: Burnup & Burndown with Forecast

1. Where the code runs

Entirely on Atlassian Forge. There is no server of ours, no container of ours, and no externally reachable endpoint of ours. The app consists of a Forge-hosted resolver function and a Custom UI bundle served from Atlassian's CDN. Atlassian is the operator of the runtime.

2. Permissions and identity

The app requests exactly one scope: read:jira-work. It does not request write:jira-work, manage:jira-configuration, or any administrative scope. Every Jira request is made as the viewing user, so Jira's own permission scheme is the security boundary — the app cannot surface an issue to someone who is not allowed to see it.

3. Network access

The app declares no external egress and makes none. It does not call any third-party API, and it has no API tokens or credentials of any kind to leak. There is no webhook, no web trigger endpoint, and no scheduled job that could be invoked from outside Jira.

4. Secrets

There are none. The app stores no secrets, environment variables, API tokens, or customer credentials — neither in Forge storage nor anywhere else.

5. Data handling

See the privacy policy for the exact list of fields read and the one-hour cache record written. In short: issue keys, creation dates, statuses and status transition timestamps; nothing else; retained for one hour.

6. Reporting a vulnerability

Write to wangxydlut@gmail.com with enough detail to reproduce the issue. Please do not open a public issue before we have had a chance to respond. We will acknowledge your report and tell you what we found.
