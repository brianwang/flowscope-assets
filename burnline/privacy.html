Privacy Policy

Burnline: Burnup & Burndown with Forecast

Last updated: 1 October 2026

This app is a Jira dashboard gadget published on the Atlassian Marketplace by the Marketplace partner flowscope (referred to below as "we"). This page describes exactly what the app does with data. It is written to match the app's source code, not to describe a general policy.

1. What the app reads

The app reads Jira issues through the official Jira REST API, using the read:jira-work scope and nothing else. Every request is made as the user who is viewing the gadget — the app can only ever see the issues that the person looking at the dashboard is already allowed to see. It never uses an administrator identity, and it cannot read anything a viewer could not read themselves.

For issues matched by a JQL filter that a Jira administrator configures on the gadget, it reads:

  • the issue key (for example ABC-123)
  • the issue creation date
  • the issue's current status
  • the issue's status transition history — which status it moved to, and when

The app does not read issue summaries, descriptions, comments, attachments, custom field values, user profile details, email addresses, or any other content.

2. What the app stores

For one hour, the app caches the computed result of the chart so that a dashboard reload does not re-query Jira. That cached record contains:

  • a hash of the gadget's settings, and the Atlassian account ID of the user who loaded it (so two people on the same dashboard never see each other's cache entry)
  • the numbers that make up the chart: daily counts of items in scope, items delivered, items remaining, and the weekly throughput counts
  • counters for items that could not be classified, and — only when some items fell into that case — up to five issue keys, so the chart can name them instead of silently dropping them

No summaries, descriptions, comments, or field values are stored. The cache lives in Atlassian Forge hosted storage, which is hosted by Atlassian, not by us.

3. What the app does not do

  • It does not send any data to us or to any third party. The app makes zero outbound network requests — the only host it talks to is your own Atlassian site, through the Atlassian-provided API.
  • It does not use analytics, telemetry, crash reporting, or advertising SDKs.
  • It does not create, modify, or delete anything in Jira. It is read-only.
  • It does not read or store Atlassian account credentials, API tokens, or passwords.

4. Sub-processors

None. There is no third-party sub-processor, because there is no third-party data flow.

5. Retention and deletion

Cached records expire one hour after they are written and are then ignored. Uninstalling the app removes the app's Forge storage. To have a cache entry removed sooner, uninstall and reinstall the app, or contact us at the address below.

6. Data residency

The app runs on Atlassian Forge and stores data in Atlassian Forge hosted storage in the region Atlassian assigns to your product. We do not choose or move that region, and because there is no egress there is no cross-border transfer by us.

7. Your rights

Because the app stores no personal data beyond a cache keyed to your Atlassian account ID, the practical way to exercise a deletion request is to uninstall the app, which clears its storage. If you need something specific, write to us and we will tell you exactly what is in the storage, or remove it.

8. Changes to this policy

If the app's behaviour changes, this page changes with it. The "last updated" date above is the date of the last change.
