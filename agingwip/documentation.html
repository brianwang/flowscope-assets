Aging WIP Chart for Jira Dashboard

Last updated: 1 October 2026

This page covers everything the app does. It is written to match the app's behaviour, including the parts that are unflattering — where the numbers can mislead, this page says so.

1. What the app does

It is a Jira dashboard gadget that shows how long work has been sitting still. You give it a JQL filter. For every work item that has not finished yet, it measures the time since that item last changed status — which is exactly how long it has been in the status it is in now:

  • x — the date the item entered its current status
  • y — how many days it has been there

Four horizontal lines are drawn on top: the 50th, 70th, 85th and 95th percentiles of those ages, each labelled in days. A summary line shows the sample size and the percentile values.

Why percentiles and not an average: the useful question is not "how long does work usually sit" but "how long has the worst of it been sitting". Items past the 85th percentile are highlighted, because that tail is the work that is quietly not moving.

No status configuration is needed. The app reads each item's own history, so the moment it entered its current status is a fact in the data, not something you have to tell it. Items that have never changed status at all are counted from their creation date, and that count is shown separately.

2. Requirements

  • Jira Cloud.
  • A dashboard you can edit.
  • The JQL filter you want the chart scoped to — for example project = ABC.

3. Add the gadget to a dashboard

  1. Open a Jira dashboard and choose Edit.
  2. Choose Add gadget and search for Aging WIP Chart.
  3. Add it, then open its configuration (the gadget's menu → Configure).
  4. Fill in the setting below and choose Save.

4. Settings

JQL filter

Which issues the chart is built from. Use the Preview button to see how many issues currently match before you commit to a filter. Items that have already finished are excluded automatically — this chart is about work that is still in flight.

No status pickers

There is nothing to configure here. The app reads each item's own status history, so the moment it entered its current status is a fact in the data rather than something you have to tell it. This also means the gadget keeps working when your Jira is displayed in another language — no status name is ever typed or stored.

Statuses are stored by ID, not by name. Jira instances often contain several statuses that share one name (for example, more than one status called Done). If two statuses in the list have the same name, the app shows a #id after each so you can tell them apart. Because the ID is what is saved, changing your Jira display language does not break an existing gadget.

5. How the age is counted

These rules exist because Jira's history does not always contain a clean "entered" event. The app resolves each case explicitly rather than guessing:

  • Calendar days, not working days. A weekend counts.
  • Items that moved back into a status they had before — the last transition is used, so an item that bounced back is measured from when it came back.
  • Items that have never changed status at all — there is no transition to read, so the clock starts at creation. These are counted separately and the count is shown, so you can judge how much they affect the chart.
  • Items where even that cannot be established are excluded — and the number excluded is always displayed. They are never quietly counted as zero, because a zero would drag the percentiles down and look like good news.

6. Percentile lines and sample size

A 95th percentile calculated from 20 issues is, in practice, just the largest of those 20 numbers. It is not an estimate of anything.

The app therefore only draws a percentile line when there is enough data for it to mean something. Below that threshold the line is omitted, and the gadget shows why instead of drawing a line that would be mistaken for a measurement.

7. Languages

The gadget interface is available in English and Chinese (Simplified). Because statuses are stored by ID (section 4), a gadget configured in English keeps working when Jira is switched to another display language.

8. Data and privacy

The app reads issues through the Jira REST API using a read-only scope. It does not send data to any external service, and it has no third-party integrations. The full description of what is read, what is stored and where is in the privacy policy.
