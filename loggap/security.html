Security

Worklog Coverage for Jira

Platform

This is a Forge app. It runs on Atlassian's infrastructure, not on any server operated by the developer. There is no external backend to be compromised, no self-hosted endpoint, and no outbound network access configured.

Permissions

It requests exactly one scope: read:jira-work. It does not request any write scope, any admin scope, or any Confluence scope.

Data egress

None. The app declares no external fetch permissions and calls no host other than your Jira site's own REST API. Because it makes no external calls, it is eligible for Atlassian's Runs on Atlassian program.

Credentials

The app collects no credentials of any kind — no Atlassian API tokens, no passwords, and no third-party service tokens. All Jira requests are made on behalf of the signed-in user through Forge's own authorization layer.

What it cannot do

  • It cannot see work items the viewing user cannot see — requests are made as that user, so Jira's own permission scheme applies.
  • It cannot modify anything in Jira.
  • It cannot send data anywhere outside Atlassian.
