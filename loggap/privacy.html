Privacy

Worklog Coverage for Jira

What the app reads

It reads Jira work item data through Jira's own REST API, as the user viewing the gadget (read:jira-work). That means it can only ever see work items that the viewing user can already see in Jira. The fields it reads are:

  • work item key and summary
  • assignee
  • time spent (timespent)
  • status category
  • resolution date

It is read-only. It does not create, edit, transition, comment on, or delete anything, and it does not write worklogs.

Where data goes

Nowhere outside Atlassian. The app makes no network requests to any host other than your own Jira site's REST API. There is no third-party analytics, no telemetry, no external logging service, and no external database.

What is stored

The app keeps a short-lived cache of the computed result (coverage counts, per-assignee totals, a list of work item keys) in Atlassian-hosted Forge storage. The cache:

  • expires after 1 hour;
  • is keyed by the viewing user's account ID, so one user's cached result is never served to another;
  • holds counts and work item keys only — no work item descriptions, comments, or attachments.

If the cache write fails, the app still works and simply re-reads Jira each time.

Data retention

Nothing is retained beyond that 1-hour cache. Uninstalling the app removes it. The app has no way to export data and no separate data store of its own.
