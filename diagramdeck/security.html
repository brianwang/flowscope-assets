Security Policy

Mermaid Diagram for Confluence

Last updated: 2 October 2026

This page states how the app is built and what it can and cannot reach. It is written to match the app's source code and its Forge manifest.

1. Where the code runs

ComponentWhere it executes
Rendering and configuration UI The end user's browser, inside a sandboxed Forge iframe in the Confluence page.
Backend There is none. The app declares no Forge function module and no resolver. No code of ours runs on Atlassian's servers.

There is no infrastructure operated by the publisher. The app has no server, no database and no hosting of its own.

2. Permissions and identity

The app requests no OAuth scopes. It cannot read Jira issues, Confluence content, user profiles or space permissions, because it has not been granted the ability to do so.

The app never asks for an Atlassian API token, a password or any other shared secret. There is nothing for a user or an administrator to generate, copy or paste.

3. Network access

The app makes no outbound requests to any host. Its Forge manifest declares no external egress domains. The diagramming library is bundled inside the app rather than fetched from a CDN.

4. How user input is handled

The app's input is arbitrary text typed by a user, and it is turned into an SVG image that is inserted into the Confluence page. That is a potential injection path, and it is handled deliberately:

  • The diagramming library runs in strict security mode, which sanitises the generated SVG before it is inserted.
  • The app inserts only the sanitised SVG. It does not interpret the input as HTML, script or markup of any other kind.
  • Input is length-limited, so a single macro cannot be used to make a page unresponsive.

5. What this page does not claim

The app holds no security certification, no independent audit and no compliance attestation (for example SOC 2, ISO 27001 or a completed CAIQ). Nothing on this page should be read as claiming otherwise. Where the app relies on Atlassian's own controls — infrastructure, the Forge iframe sandbox, storage, logging — those are described in Atlassian's own security documentation, not here.

6. Reporting a vulnerability

Please email wangxydlut@gmail.com with a description of the issue and, where possible, the steps to reproduce it. Please do not open a public issue for a security report.

This is a small app maintained by one person. Reports are handled on a best-effort basis and there is no guaranteed response time and no bug bounty programme.
